# 架构

初版只做一件事：在用户分配的 Safari 后台标签页中读页面、填表和点击。

```text
MCP → JS client → localhost broker ← Swift native handler ← Safari extension → 页面
```

- 扩展负责标签页和 DOM，popup 负责分配、查看、暂停和释放。
- Swift handler 只转发本地配对、轮询和结果，不实现页面操作。
- broker 保存分配的标签页和短期请求结果；MCP 提供工具接口。
- 内部版本固定为 `0.1`，两端一起更新。不维护独立协议草案、生成类型或兼容协商框架。

Safari 直接使用现有页面的登录状态。工具不导出 Cookies，不启动另一套浏览器。用户选中任务页时暂停写入；人机验证由用户在原页面处理后恢复。DOM 事件不等于原生可信输入，复杂编辑器及截图暂不支持。

保留的最小检查：本机连接认证、标签页及站点匹配、前台暂停、请求去重。已有站点权限直接复用；缺少权限时在按钮点击的同步调用栈中调用 Safari 权限 API。

`unknown` 表示动作可能已发出，不能直接再点一次。请求结果在内存中保留十分钟；重启服务不会恢复任务。详见 [验证记录](validation.md)。
